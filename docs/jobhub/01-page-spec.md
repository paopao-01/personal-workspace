# JobHub V0.1 页面规格

> 本文是 `jobhub-prd.md` 的界面与交互补充。它定义 V0.1 应呈现什么、用户如何操作以及边界状态如何反馈；不替代领域规则和接口契约。

## 1. 范围与体验基线

- 形态：本地单用户 Web 应用，桌面端优先；窄屏仅保证日程、提醒、快速复盘与任务可用。
- 核心承诺：用户可在首次会话内完成「粘贴 JD → 确认要求 → 做出投递判断 → 保存下一步行动」。
- 信息优先级：临近面试、待复盘、逾期行动/任务优先于统计；无有效样本时不展示趋势图或百分比。
- 人工确认：候选岗位要求、自动建议和任何未来 AI 结果均以“候选”样式呈现，用户确认前不影响确定性结论。
- 表单策略：除创建岗位、创建投递、创建面试和快速复盘的最小字段外，其余允许跳过和后补；离开表单时保存草稿。

## 2. 全局框架

### 2.1 导航与路由

| 区域 | 路由 | 主任务 |
|---|---|---|
| 首页工作台 | `/dashboard` | 识别今天最该做的动作 |
| 岗位与投递 | `/jobs`、`/jobs/:jobId`、`/applications/:applicationId` | 分析 JD、记录决定和管理投递 |
| 面试中心 | `/interviews`、`/interviews/:interviewId` | 安排、准备和复盘面试 |
| 学习任务 | `/tasks` | 完成并验证改进任务 |
| 能力与证据 | `/skills`、`/projects`、`/evidence-attachments` | 渐进补充技能、项目案例和附件引用元数据 |
| 设置 | `/settings` | 时区、提醒节点、导出和最近删除 |

桌面端采用左侧主导航、顶部全局“新增”按钮和主内容区。全局“新增”菜单只包含：新增岗位、新增投递、新增面试、新增任务。列表详情在同一主内容区打开，不使用多层弹窗承载复杂编辑。

### 2.2 通用组件与状态

| 组件 | 行为 |
|---|---|
| 状态标签 | 显示业务状态与文字，不只依赖颜色；状态变化须走明确操作按钮。 |
| 来源说明 | 差距、准备优先级、薄弱点等结论提供“查看依据”，可定位至 JD 片段、问题或任务。 |
| 下一步行动卡 | 显示动作、截止时间、关联投递和“完成/编辑”操作；逾期时明确显示逾期天数。 |
| 空状态 | 说明此页面可得到的价值，并提供唯一的推荐操作；不显示零值图表。 |
| 删除确认 | 显示直接与间接影响数量；永久删除需二次确认。 |
| 反馈消息 | 保存、创建、状态转换使用轻提示；非法转换或校验失败在字段/操作附近说明原因。 |

所有时间以用户当前时区展示；若面试的事件时区不同，则同时显示原始时区。所有列表默认保留用户上次使用的筛选条件。

## 3. 页面规格

### P01 首页工作台 `/dashboard`

**目标**：让用户在 10 秒内知道今天应做什么。

| 区块 | 内容与排序 | 可操作项 |
|---|---|---|
| 今天应做什么 | 按“临近面试 → 待复盘 → 逾期下一步行动 → 逾期任务 → 即将到期任务”排序；每项显示来源和截止时间。 | 完成/编辑行动、开始复盘、打开准备包、打开任务。 |
| 未来 7 天面试 | 时间线显示轮次、公司、方式、准备状态。 | 查看详情、改期、取消、打开准备包。 |
| 进行中投递 | 显示当前状态、下一步行动、截止时间；无行动项置顶并提示补充。 | 更新状态、补充行动、打开投递详情。 |
| 最近薄弱点 | 只在有题目数据时显示前 5 个知识点及最近表现；不显示“能力分”。 | 查看原始问题、创建/打开关联任务。 |
| 最近岗位 | 最近查看或最近更新的岗位。 | 继续确认要求、查看差距、创建投递。 |

空状态：没有岗位时，主按钮为“粘贴一份 JD 开始”；已有岗位但没有投递时，推荐“为岗位做出投递判断”。

### P02 岗位收集箱 `/jobs`

**目标**：管理岗位、快速筛选下一份值得处理的 JD。

- 表格字段：公司、岗位、地点、决策状态、已确认关键要求数、差距概览、最近更新时间、是否存在有效投递。
- 筛选：决策状态、岗位状态、地点、来源、是否存在待确认要求；支持关键词搜索公司与岗位名称。
- 行操作：查看详情、归档、恢复；归档前提示关联投递与面试数量。
- 新增入口：打开“粘贴 JD”表单。必填公司、岗位名称、JD 原文；保存成功后进入 P03，而非回到列表。

### P03 岗位详情与 JD 确认 `/jobs/:jobId`

**目标**：把一份 JD 转为可解释的投递判断和准备输入。

页面分为四个固定区域：

1. **岗位摘要**：公司、岗位、地点、来源、薪资、JD 原文链接；支持编辑和归档。
2. **投递决定**：`TO_APPLY / APPLY / DEFER / IGNORE` 单选，决策理由可选；选择 `APPLY` 时引导创建投递，已存在有效投递时跳转至该投递。
3. **候选要求确认**：按必须、加分、职责、经验、业务领域和待确认分组。每项显示原始片段、标准技能、候选类型、确认状态。可确认、编辑、忽略、删除、合并；批量操作仅限同类候选项。
4. **差距清单**：仅基于已确认要求生成。状态为“已满足且有证据 / 自评满足但缺少证据 / 不满足 / 信息不足 / 待确认”，每项可查看依据和手动修正原因。

首次进入时突出 3–5 项最影响投递或准备的候选要求；候选不足时展示全部。待确认候选不得计入差距结论。

**关键操作规则**：修改 JD 原文后，已有候选要求均标记为待重新确认；不删除历史手动确认记录。未建立能力资料时，差距应显示“信息不足”，不能显示“不满足”。

### P04 投递详情 `/applications/:applicationId`

**目标**：把投递状态变成有截止时间的下一步行动。

| 区域 | 内容 |
|---|---|
| 投递摘要 | 公司、岗位、渠道、投递日期、简历版本、联系人、期望薪资。 |
| 当前状态 | 状态标签与可执行的目标状态按钮；非法目标状态不显示为可操作按钮。 |
| 下一步行动 | 动作文本、截止时间、完成状态；进行中投递缺失行动时显示醒目提示。 |
| 时间线 | 投递状态变更、面试创建/改期/取消、行动完成等事件，按时间倒序。 |
| 面试列表 | 关联面试、轮次、时间、日程状态、结果和“准备/复盘”入口。 |

创建投递时必填岗位与投递日期，默认状态为 `DRAFT`；进入 `APPLIED` 后建议填写下一步行动，但不自动替用户填值。用户创建面试或完成复盘时，系统可提出行动更新建议，必须由用户确认。

### P05 面试中心 `/interviews`

**目标**：查看和管理未来面试及待复盘事项。

- 默认视图为未来 7 天时间线；可切换列表与月视图。
- 卡片显示公司、岗位、轮次、开始时间/时区、方式、日程状态和准备状态。
- 筛选：日期范围、日程状态、投递状态、面试方式。
- 创建面试：必填投递、轮次、开始时间、事件时区；可选方式、会议链接/地址、联系人、准备事项。
- 改期、取消、完成均为专用操作。取消或缺席时，结果字段禁用并清空未确认的通过/失败选择。
- 到达预计结束时间且日程仍为 `SCHEDULED` 时，显示“等待确认是否完成”的提示，不自动修改日程状态。

### P06 面试详情 `/interviews/:interviewId`

**目标**：成为单场面试的操作入口。

顶部显示面试摘要、关联投递、时间/时区、日程状态和结果。主要操作随状态变化：

- `SCHEDULED`：改期、取消、打开准备包、标记完成。
- `COMPLETED`：开始/继续复盘、查看准备包。
- `CANCELED` 或 `NO_SHOW`：查看记录，不显示复盘创建入口。

下方依次展示准备事项、提醒计划、复盘状态和关联任务。提醒只说明“进入应用后可见”，不可承诺操作系统推送；`FAILED` 提醒展示失败原因、尝试次数和“重试”操作，重试需要当前版本并重新排队。

设置页的 AI 供应商列表支持删除配置。删除前显示不可恢复提示；激活中的供应商和已被 AI 任务引用的供应商不可删除，并说明需要先切换供应商或保留配置以维持历史审计。

### P07 面试准备包 `/interviews/:interviewId/preparation`

**目标**：将本场面试所需准备集中为可执行清单，替代用户跨页面翻找资料。

| 区块 | 展示规则 |
|---|---|
| 本场优先准备项 | 按用户已确认岗位要求、面试临近程度、近期薄弱表现、任务截止时间排序；每项必须展示排序依据。 |
| 岗位要求与差距 | 显示必须要求、加分要求和当前差距状态；待确认项单列，不混入准备结论。 |
| 可讲项目案例 | 展示与要求关联的“场景—方案—问题”摘要和外部证据引用；没有资料则显示待补充。 |
| 历史问题 | 按知识点展示最近问题、回答状态、来源面试和错误原因。 |
| 未完成任务 | 展示关联知识点、截止时间、验证方式和状态；支持跳转任务详情。 |
| 准备事项 | 面试级检查清单，支持完成勾选；不改变学习任务状态。 |

准备包不生成综合能力分数，不修改用户能力等级。用户可从每一项跳转至原始 JD 片段、问题、任务或项目案例。

### P08 快速/完整复盘 `/interviews/:interviewId/review`

**目标**：让用户在面试后低成本留住可行动的信息。

快速复盘必填：面试结果，以及至少一道问题或明确选择“未记录到问题”；每道问题须选择“完全答出 / 部分答出 / 未答出”。保存后状态为 `DRAFT`，用户可随后补全。

完整复盘在同页展开附加字段：问题类型、知识点、我的回答、参考答案、难度、错误原因、改进方案、面试官关注点、项目表达与真实性风险、岗位意愿。每道问题可发起 AI 分类；填写“我的回答”后还可发起回答质量分析；部分答出或未答出的问题还可发起 AI 学习任务建议。三类结果均以可编辑候选显示，用户逐项采纳或拒绝后才更新对应字段或创建任务；质量分析不得改写“我的回答”、问题内容、类型、难度或知识点，学习任务建议不得自动创建任务。

每道“部分答出/未答出”问题显示“创建学习任务”操作。创建时预填知识点、来源问题、建议验收标准和验证方式，用户确认后才创建任务。复盘完成后仍可编辑，页面显示最后修改时间。

### P08A 复盘分析 `/reviews/analysis`

按面试开始日期和可选岗位筛选，展示复盘问题的原始回答状态计数、知识点和问题类型分布、面试结果汇总。填写完整的当前与对比日期窗口后，额外展示两窗的完全答出、部分答出、未答出及题目总数，并保留两个窗口边界；该对比不生成能力标签、趋势结论或学习任务建议。

### P08B 渠道与简历版本效果对比 `/analytics/channel-effectiveness`

按投递日期范围（可选）筛选，展示两张原始计数表：按投递渠道（`application_record.channel` 原始填写文本）分组、按简历版本（`application_record.resume_version` 原始填写文本，未填写归为「未指定版本」）分组。每组展示投递数、面试数、Offer 数原始计数；Offer 率仅在样本充足（`applicationCount >= 2`）时显示，否则显示「信息不足」。页面明确标注：计数采用状态近似口径（面试数 = `INTERVIEWING`/`OFFER`，Offer 数 = `OFFER`），不 JOIN 面试记录；渠道与版本按原始填写文本分组，不做归一化或去重；不输出趋势结论、能力等级、归因或行动建议。

### P08C 投递漏斗转化趋势 `/analytics/funnel`

按投递日期范围（可选 `from`/`to`，`datetime-local`，留空=不过滤，前端将本地时间转 UTC ISO 后提交）与时间粒度（`granularity`，`day` 或 `hour`，缺省 `day`）筛选，以 `GET /api/analytics/funnel?from=ISO&to=ISO&granularity=day|hour`（只读，无需确认头与幂等键）拉取按 `applied_at` 分组的时间序列。按 `date` 升序展示表格，列含「日期」（`day` 粒度如 `2026-09-07`、`hour` 粒度如 `2026-09-07T13:00:00Z`）、「投递数」（`applied`，`status != 'DRAFT'`，漏斗顶部）、「面试数」（`interviewed`，`status IN ('INTERVIEWING','OFFER')`）、「Offer 数」（`offered`，`status = 'OFFER'`）、「面试转化率」（`interviewRate`，百分比展示）、「Offer 转化率」（`offerRate`，百分比展示）。只展示有投递记录的桶，缺失日期/小时不补 0 行（与后端不补 0 一致）；空匹配显示「无趋势数据」。提供 `day`/`hour` 粒度切换（下拉，默认 `day`，切换重置趋势不重置其他）。页面明确标注：计数采用状态近似口径（同 P08B），不 JOIN 面试记录；分母为 `applied`（已投递），`applied` 为 0 时转化率兜底 0；不输出趋势结论、能力等级、归因或行动建议。趋势随过滤变更刷新，不改变其他状态，不落盘后端、不动任何业务表。

### P09 学习任务 `/tasks`

**目标**：把薄弱点转为可验证的改进，而非仅记录待办。

- 默认排序：逾期、临近截止、与最近面试关联、优先级、创建时间。
- 筛选：状态、知识点、来源类型、截止时间、关联岗位/面试。
- 任务卡：名称、状态、截止时间、知识点、来源、验收标准、验证方式、验证结果摘要。
- 状态操作：开始、完成、放弃、恢复；完成时可填写验证结果，未填写时提示但允许保存为“未验证完成”。
- 同一知识点的多个问题可关联至一项任务；任务完成不自动修改 `self_level`，也不自动移除薄弱点。
- 任务详情新增「完成证据」区块：以 `GET /tasks/{taskId}/evidence`（详情接口已回显 `evidenceRefs`）列出已挂载证据（标题、类型、链接/路径；证据在回收站时显示"来源已删除"，恢复后自动还原）。
- 挂载入口：从证据列表选择已有证据（下拉/搜索），`POST /tasks/{taskId}/evidence` 挂载；重复挂载静默幂等（提示"已挂载"，不重复插入）。卸载入口：每条证据旁提供"卸载"按钮，`DELETE /tasks/{taskId}/evidence/{evidenceId}`，无确认头（本地单用户，卸载可重新挂载）。
- 证据挂载不依赖任务状态（任何状态可挂载/卸载，包括已完成/已放弃），不替代 `verificationResult`/`outputUrl` 自由文本字段（三者并存），不改变任务 `version`/`status`；完成状态操作不受证据挂载影响（未挂载证据也可完成，标记"未验证完成"）。

### P10 能力与证据 `/skills`、`/projects`

**目标**：以低成本补充可复用的项目表达和能力依据。

- 技能页显示自评等级、证据状态、面试表现三个独立维度；三者不得相互自动覆盖。
- 新建项目案例只要求“使用场景、采取方案、解决问题”，结果、数据和链接可以后补。
- 证据以外部链接或用户填写的本地路径引用为主；界面必须提示应用不会自动读取或上传被引用的文件。
- 附件引用库允许一条证据登记多条本地路径或外部链接，支持人工填写类型、大小和说明；应用不读取、扫描、上传、下载或校验引用位置指向的内容。删除进入最近删除，恢复只恢复引用记录。
- 用户可从技能、项目或证据页补充关联，但首次 JD 分析不强制进入本页。
- 技能画像行下提供可展开「自评历史」区块：调用 `GET /api/skills/{skillId}/self-level/history`（只读，按时间升序）展示等级变更轨迹文本（如 `3 → 5 → 4`）与列表（时间/from→to/reason）。在轨迹文本上方提供轻量 sparkline 折线图（内联 SVG，无图表库依赖）：以每条历史行的 `toLevel`（0–5）按 `occurredAt` 升序为数据点连成折线，首次自评 `fromLevel=null` 也以 `toLevel` 作为一个点，Y 轴固定 0–5（等级域），X 轴时间正序不标具体日期，每个数据点 hover 显示「等级 N · <时间>」；折线是可视化补充，不替代下方轨迹文本与表格，不输出趋势结论、能力等级、归因或行动建议。从未自评显示「暂无自评历史」（折线不渲染）；技能不存在为 404。历史随 PUT 自评实时刷新，不改变三维度独立性，不落盘额外推断。

### P11 设置与数据管理 `/settings`

包含时区、默认提醒节点、通知渠道、导出 JSON、最近删除和恢复。导出前展示数据范围与不包含的密钥/运行日志；恢复前展示影响范围。P0 不提供 CSV、跨端同步或系统级通知设置。

通知渠道区块并列展示 BROWSER、EMAIL、WEBHOOK 三个卡片，每个渠道独立启用开关、配置表单、测试通知按钮和投递状态回显：

- BROWSER：受浏览器通知权限；启用后前端展示系统通知并回执，权限被拒仍保留站内通知。
- EMAIL：配置 SMTP 主机、端口、用户名、密码、发件/收件地址与 STARTTLS；密码留空表示保留既有凭据；测试通知展示投递 SENT/FAILED 与失败原因。
- WEBHOOK：配置 webhook URL（必填）、可选 secret（留空保留既有凭据，不回显）与可选 providerType（FEISHU/DINGTALK/WECOM，仅存档透传，不驱动签名）。测试通知由服务端同步 POST 到 URL，按 HTTP 响应展示 SENT/FAILED 与失败原因。

各渠道失败不阻塞其他渠道，站内通知始终保留兜底。WEBHOOK 渠道不接受前端回执，ack 仅 BROWSER。

加密备份区块提供 passphrase 输入框（type=password）与「立即加密备份」按钮：

- 点击按钮以输入的 passphrase 触发 `POST /api/backups`；成功后刷新备份列表并提示「已生成 <fileName>」。
- passphrase 输入框在提交后立即清空，仅写入不回显；列表与详情不显示 passphrase、不显示解密内容。
- 备份列表（最新优先）展示创建时间（用户时区）、文件名、大小与下载按钮（`GET /backups/{id}/download`）。每条记录提供删除按钮：点击后内联二次确认（「删除后不可恢复，是否继续？」），确认后以 `DELETE /api/backups/{id}` 携带 `X-Confirm-Permanent-Delete: true` 头删除；成功后提示「已删除 <fileName>」并刷新列表。删除为物理删除，不可恢复，不进入最近删除。后端在删除成功后向 `audit_log` 追加一条 `action=BACKUP_DELETED` 审计记录，事后追溯可经设置页「审计日志」区块按 `action=BACKUP_DELETED` 过滤查询（见下）。每条记录另提供「密钥轮换」按钮（见下）。
- 按龄批量清理：历史备份列表区提供「清理 N 天前」输入框（整数 ≥1）与「清理」按钮，点击后内联二次确认（「将物理删除 N 天前的全部备份，不可恢复，是否继续？」），确认后以 `DELETE /api/backups?olderThanDays=N` 携带 `X-Confirm-Permanent-Delete: true` 头清理；成功后提示「已清理 X 条备份（Y 个文件，<是否置空 last_backup_id>）」并刷新列表。无匹配记录时提示「已清理 0 条」；缺阈值或确认头时后端返回 400 并提示。后端对每个被删记录向 `audit_log` 追加一条 `action=BACKUP_PURGED_BY_AGE` 审计记录，事后追溯可经「审计日志」区块按该 action 过滤查询。

- 密钥轮换：每条备份记录的列表项内提供「密钥轮换」按钮，点击后弹出表单含「旧口令」与「新口令」两个 passphrase 输入框（均 type=password，min 8）及「确认轮换」按钮，以 `POST /api/backups/{id}/rotate-key`（body `{oldPassphrase, newPassphrase}`，写操作携带 `Idempotency-Key`，非销毁性无需 `X-Confirm-Permanent-Delete`，旧口令解密成功即授权）提交；成功后提示「已轮换 <fileName> 的保护口令」并刷新列表（记录 id、创建时间与文件名不变，仅 sizeBytes 可能变化）。新口令输入框下方复用客户端 passphrase 强度计（提示性，未达强被后端拒绝）。失败按错误码提示：旧口令错误或文件损坏（422）、新口令未达强（400，含 score 与失败规则）、记录不存在（404）。两个 passphrase 输入框在提交后立即清空，仅写入不回显；列表与详情不显示 passphrase、不显示解密内容。后端在轮换成功后向 `audit_log` 追加一条 `action=BACKUP_KEY_ROTATED`、`resourceType=BACKUP_RECORD` 的审计记录，事后追溯可经设置页「审计日志」区块按 `action=BACKUP_KEY_ROTATED` 过滤查询。

### P12 模拟项目面试 `/mock-interviews/:mockInterviewId`

从项目与证据页的每个已保存项目案例启动。页面展示异步生成状态；成功后显示基于项目快照的讲解稿和一个高频追问。活动会话提供当前问题的作答输入框；保存后回显回答并轮询下一道 AI 追问，随后可继续作答。每条已保存作答提供一次“获取 AI 评分”操作，生成期间显示等待状态，成功后展示 1–5 分、反馈和评分依据；评分只作为练习反馈，不会修改原项目事实或创建学习任务。页面还显示所有已完成评分的数量、会话数、分布和最近五次原始分数；少于两条时明确显示信息不足。用户可填写当前和对比两个完整时间窗口查看各窗原始评分统计；只有两个窗口均至少两条评分才显示“当前减对比”的平均分差，并明确该值不是能力等级或自动行动建议。仍可通过专用操作结束或取消会话。

### P13 简历版本 `/resume-versions`

用户手工保存版本名称和确认过的简历原文；页面可选择任意两个不同版本并显示逐行相同、新增和删除。对比不调用 AI，不判定哪个版本更好，不自动替换主简历或投递字段。

## 4. 页面间关键路径

### 首次价值路径

`P02 新增岗位 → P03 确认要求与差距 → 保存投递决定 → 创建投递/保存下一步行动 → P01 查看行动`

### 面试准备路径

`P04 创建面试 → P06 面试详情 → P07 面试准备包 → P09 完成关联任务`

### 改进闭环路径

`P06 标记完成 → P08 快速复盘 → 创建任务 → P09 完成并记录验证 → P07 下次面试前复习`

## 5. 页面验收共性

- 页面只能显示用户已确认事实和明确标注为候选/信息不足的内容。
- 所有改变业务状态的操作必须有成功反馈；失败时说明不允许原因并保持原状态。
- 表单刷新或离开后，已保存草稿与已确认数据可恢复；未保存输入应提示用户。
- 列表、详情和核心表单在个人数据规模下应在 2 秒内呈现结果或加载反馈。
